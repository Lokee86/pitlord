# Semantic Lint Calibration

Parent index: [Diagnosis Calibration Baselines](INDEX.md)

## Purpose

This record calibrates the first language-neutral semantic lint rules over real source repositories. It is an adjudication record, not a claim that the existing 16-corpus architecture suite provides semantic-language coverage.

## Scope

The frozen architecture corpus is mostly C#, Java, Kotlin, LotusScript, C++, and GDScript. Only two frozen repositories currently exercise the implemented Rust, TypeScript/JavaScript, and Python semantic adapters:

- Lexicanter at `eac754788b3cf18a930c085c1c49f8f353e18107`;
- Space Rocks Clean v1 at `361dcdb4054725c8f1bb58727ff402fcfedf6d18`.

The rules under calibration are:

- `swallowed-error`;
- `unobserved-outcome`.

Lexicon owns semantic fact extraction. Arcana transports those facts unchanged. Pitlord owns the reusable rule semantics.

## Initial audit

The first frozen-corpus pass produced:

| Corpus | Adapter | Findings |
| --- | --- | ---: |
| Lexicanter | Rust | 1 `swallowed-error` |
| Lexicanter | TypeScript | unresolved: whole-repository analysis did not complete because a checked-in generated bundle is about 1.7 MB |
| Space Rocks | TypeScript/JavaScript | 2 `swallowed-error`, 1 `unobserved-outcome` |
| Space Rocks | Python | 6 `swallowed-error` |

Two concrete adapter defects were found.

### Generated semantic sources

Two Space Rocks TypeScript findings came from Plasmic-generated TSX files that explicitly identify themselves as auto-generated and not editable. Semantic linting those files creates non-actionable findings.

Lexicon now omits semantic protocol facts for files whose first 4 KiB contain an existing trusted generated-source marker such as `code generated`, `do not edit`, `@generated`, `<auto-generated`, or `auto-generated file`.

This suppression is semantic-only. It does not remove ordinary structural graph facts for those files.

### Import fallback recovery

One Python finding came from the standard compatibility pattern:

`try import tomllib -> except ModuleNotFoundError -> import tomli as tomllib`.

An import performed inside an exception handler is explicit recovery. Python semantic extraction now emits `error-action:recover` for `import` and `from ... import ...` statements inside handlers.

This deliberately does not treat every `pass` handler as recovery.

## Rerun

After those fixes and adapter regression tests, the frozen-corpus rerun produced:

| Corpus | Adapter | Findings |
| --- | --- | ---: |
| Lexicanter | Rust | 1 `swallowed-error` |
| Space Rocks | TypeScript/JavaScript | 1 `unobserved-outcome` |
| Space Rocks | Python | 5 `swallowed-error` |

The two generated TypeScript findings disappeared. The import-inside-handler Python finding disappeared. The independent findings remained stable.

## Adjudication

### Lexicanter Rust swallowed error

`library/tadpole_ffi/src/lexc/mod.rs:51` contains `Err(_) => {}` while parsing input lines. This genuinely discards a parse error without propagation, recording, or an explicit recovery action. It remains a valid advisory finding.

### Space Rocks unobserved outcome

`web-astro/src/components/Homepage.tsx:91` calls `document.fonts?.ready.then(scheduleFit)` without observing the returned Promise. The adapter has sufficient async type evidence to prove the outcome obligation. The finding is semantically valid, although equivalent language-native linting may also detect this class of issue.

### Space Rocks Python swallowed handlers

The five-handler rerun motivated a downstream error-flow seam. Lexicon semantic adapters can now attach normalized flow facts to otherwise empty handlers: `fallback`, `enclosing-propagation`, `intentional-suppression`, or non-dispositive `continuation`. Pitlord suppresses `swallowed-error` for the first three but deliberately not for `continuation`.

A second frozen rerun reduced Space Rocks Python from five advisories to one:

- the two optional-dependency fallback chains are represented as `fallback`;
- the path-resolution fallback is represented as `fallback`;
- best-effort cleanup followed by propagation of the primary failure is represented as `enclosing-propagation`;
- the validation path that catches a secondary parse failure and then appends the original rich error is represented only as `continuation`, so it remains advisory.

Lexicanter's `Err(_) => {}` remains reportable even though later loop work continues, proving that generic continuation is not treated as recovery. A blanket exemption for empty handlers or `pass` was not added.

## Exploratory holdout evidence

A broader production-repository scan was run before tuning as a noise probe. Completed lanes showed that `swallowed-error` dominated findings while `unobserved-outcome` remained sparse. Examples included Codebase Memory MCP with 39 swallowed-handler candidates across TypeScript and Python, ctx with 31 TypeScript candidates, and Workspace MCP with 19 swallowed handlers plus 4 unobserved outcomes.

That scan was not a scored baseline: Lore's 861-file Rust pass exceeded the five-minute adapter bound and the aggregate run was stopped when another repository stalled. Those results are evidence about rule pressure and scalability, not precision/recall measurements.

## Verification

Regression suites after tuning:

- Python adapter: 25 passed;
- TypeScript/JavaScript adapter: 18 passed;
- Rust adapter: 20 passed;
- semantic-contract validator passed;
- Rust release adapter and Arcana rebuilt successfully;
- Pitlord full Go suite passed;
- frozen semantic rerun preserved Lexicanter's one Rust finding and Space Rocks' one TypeScript outcome finding while reducing Space Rocks Python swallowed-error findings from five to one.

## Conclusions

`unobserved-outcome` currently has the cleaner evidence boundary, but much of its local value may overlap language-native tooling.

`swallowed-error` now distinguishes handler-local actions from proven downstream flow. The remaining ambiguous Space Rocks case demonstrates the intended boundary: later work can be recorded as `continuation` without being promoted to recovery unless the adapter can prove fallback, enclosing propagation, or explicit suppression.

The rule should remain advisory until additional corpora validate those distinctions. Future precision work should strengthen proof of `intentional-suppression` or richer boundary/context semantics rather than treating arbitrary continuation as success.

This calibration reinforces Pitlord's product direction: prioritize semantic rules whose value comes from repository-wide, cross-file, boundary, or cross-language context rather than reproducing ordinary local linters.

## Known coverage gaps

- Lexicanter TypeScript whole-repository analysis remains unresolved because generated/bundled source is still loaded by the TypeScript program before semantic-fact suppression. Semantic suppression fixes finding quality, not compiler-program construction cost.
- Large Rust repositories can exceed the present whole-repository adapter latency budget; Lore timed out during the exploratory holdout scan.
- The frozen architecture corpus has weak Rust/TypeScript/Python representation, so semantic calibration needs additional purpose-selected corpora before precision/recall claims are warranted.
